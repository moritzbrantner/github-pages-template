# Agent discovery v1

`agent.json` is the machine-readable discovery entry point generated at the root of every site built by `@moritzbrantner/github-pages-template`.

The contract is intentionally small. It lets a software agent discover useful project surfaces without executing JavaScript or scraping visual navigation, while leaving domain semantics and authority with the consuming repository and its evidence producers.

## Location and discovery

For a project with base path `/example/`, the manifest is published at:

- `/example/agent.json`

Every HTML page generated by the template advertises the manifest with an `alternate` link whose media type is `application/json`.

## Top-level fields

- `schemaVersion`: contract version. Version 1 is the current shape.
- `kind`: `github-pages-agent-discovery`.
- `generatedBy`: the package that generated the manifest.
- `generatedFrom`: repository in `owner/name` form.
- `mode`: `full` or `augment`.
- `project`: project identity, repository, base path, and optional description.
- `discovery`: links to this manifest, `project-pages.json`, and the source repository.
- `routes`: stable human-facing project routes that agents can navigate intentionally.
- `resources`: machine-readable manifests and evidence sources.

Discovery itself never requires JavaScript.

## Standard routes

The template always describes its stable overview, stats, evidence, and preferences routes.

Consuming repositories can append project-specific routes with `agent.routes`:

- `id`: required stable machine-facing identifier.
- `label`: required short human-readable label.
- `href`: required URL or project-relative path.
- `description`: optional purpose and expected content.
- `kind`: optional route category; defaults to `page`.
- `mediaType`: optional response media type; defaults to `text/html`.

Route IDs must be unique within the configured project routes. IDs are identifiers, not presentation copy, and should remain stable when labels change.

## Resources and provenance

The manifest includes `project-pages.json` and projects configured `evidenceSources` into the resource list. Evidence source IDs, kinds, URLs, and explicit producers are retained rather than normalized into new meanings.

The template does not:

- infer benchmark semantics or thresholds;
- turn missing evidence into success;
- invent actions from buttons or other UI controls;
- collapse evidence families into a synthetic score;
- claim producer or domain authority owned by another repository.

## Consumer guidance

Prefer URL-addressable pages and meaningful query parameters for state that an agent may need to reproduce. Use semantic HTML for human pages, but do not require an agent to infer available project surfaces by crawling HTML.

Add project-specific routes only when they are durable entry points worth exposing as part of the repository's public Pages contract. Ephemeral UI states should not become manifest routes.
